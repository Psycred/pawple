## 1. Executive recommendation

**The proposed 13+ Phase 1a package — city-level meetups (bulletin board) + Moments — is not adoption-friendly as framed. It trades one friction type (18+ gate) for heavier, growth-limiting friction elsewhere: VPC, parent supervision, mixed-age safety architecture, and a product identity drift toward event discovery.**

**City selection without GPS is the low-friction, psychologically sound part of this proposal — and it applies equally to the 18+ path. Meetup RSVP for 13+ is the high-friction, high-risk part — and it directly conflicts with Legal PAW-70 and QA PAW-72 hard blocks on teen meetups.**

**Plain-language verdict:**

| Element | Adoption impact | Recommendation |
|---------|-----------------|----------------|
| **City picker (no GPS)** for coarse locality | **Supports adoption** — lower anxiety than permission prompts | **Adopt for any tier** that needs locality; optional GPS later for 18+ only |
| **Moments / journal for 13+** | **Moderate friction** — requires VPC + parent link *before any data* | **Phase 2+ only**; first surface = supervised private journal (QA), not feed |
| **City bulletin-board meetups for 13+** | **Growth-killing if shipped** — legal/compliance wall + parent veto + store child-safety bar | **Do not pursue** under 13+ pivot; keep meetups **18+ adult bucket** |
| **No mating for 13+** | **Correct** — aligns with specialist consensus | **Hard block** (non-negotiable) |

**If Founder wants lower signup friction:** the PAW-74 **18+ Phase 1a** path (OAuth + calm 18+ DOB + city picker + journal/feed/meetups, mating deferred to 1b step-up) delivers adoption gains **without** opening the teen compliance program. The 13+ pivot does **not** simplify launch — it **replaces** one gate with a larger one.

**Advisory only. Founder decides. Phase 1 remains 18+ in `docs/CURRENT.md` unless Founder re-authorizes.**

## 2. Research question answers

### Q1. First-week journey — 13+ vs 18+ adult path

#### Proposed 13+ Phase 1a journey (under evaluation)

```
Invite → OAuth → pet setup → city selection → Moments journal
                                              → browse city meetups → RSVP
(mating: off)     (no 18+ gate)   (coarse only)   (feed TBD in proposal)
```

#### Current / PAW-74-recommended 18+ journey

```
Invite → OAuth → 18+ DOB gate → pet setup → city (+ optional location prompt)
           → Moments / feed → city meetups → (Phase 1b) mating step-up
```

#### Comparative friction map (first 7 days)

| Step | 13+ proposed | 18+ (PAW-74 Pattern B / 1a) | Winner for calm adoption |
|------|--------------|----------------------------|--------------------------|
| Account creation | OAuth + invite | Same | Tie |
| Age moment | **None** (13+ entry) | One calm 18+ confirmation | **13+ wins on step count** — but only if legally processable |
| Parent/VPC | **Required before any child data** (PAW-70) — not in proposal UX | N/A | **18+ wins** — no parental program |
| Pet + city setup | Same | Same | Tie |
| Location permission | **City picker only** (proposal) | City manual + optional GPS prompt | **13+ wins** — city-only is calmer |
| First value moment | Post a Moment / see city events | Post a Moment / see feed + events | Tie on journaling; 13+ meetups add **offline risk** |
| Real-world action | RSVP to stranger-hosted event | RSVP (18+ attested) | **18+ wins** on integrity + parent trust |
| Surprise wall later | VPC/parent link may appear **after** emotional pet investment if not upfront | Mating step-up (if 1a→1b) — **predictable** if copy is honest | **18+ wins** on trust |

**Psychology insight:** Removing the 18+ gate feels like lower friction, but **parent-mediated onboarding for 13–17** (DigiLocker/VPC, parent dashboard, supervision) is **more steps and more emotional weight** than a single adult age confirmation. Meta Teen Accounts work because Meta absorbed that cost over years; Pawple Phase 1 cannot.

**First-week activation risk for 13+ meetups:** A 13-year-old who RSVPs to a city event and cannot attend (parent blocks, safety concern, empty event) experiences **broken promise** — worse for retention than never showing meetups. Empty bulletin boards in low-density cities are a **silent churn** driver.

**First-week activation for 18+ Phase 1a (PAW-74 Option B):** Journal + feed + meetups on one adult attestation tier delivers value quickly; mating step-up is optional sequencing **within** 18+, not a separate compliance program.

### Q2. City selection vs GPS permission psychology

**Recommendation: city picker is the right default for bulletin-board locality — for all ages that need coarse location.**

| Mechanism | User psychology | Parent psychology (13+) | Product fit |
|-----------|-----------------|-------------------------|-------------|
| **Manual city pick** | Familiar (dating apps, weather, events); no OS scary dialog | **Controllable** — parent sees chosen city | Matches FB Events / Meetup.com mental model |
| **GPS permission prompt** | Feels invasive; "why does a pet journal need this?" | **High veto rate** for minors | Better reserved for 18+ proximity features (mating distance) |
| **Silent GPS refresh** (current `profileLocation.js` on app open) | Invisible when granted; creepy when discovered later | **Unacceptable** for supervised teen without explicit parent consent | Keep **18+ only**; off for any teen tier |

**Current codebase alignment:** `OnboardingUserScreen.js` already collects **manual city** then offers an **optional** location phase ("Help Pawple feel local"). This is well-designed calm progressive disclosure. For bulletin-board meetups, **city alone is sufficient** — events filter by `profile.city`, not coordinates.

**Friction ranking (lowest → highest):**
1. City pre-filled from invite region / popular cities list
2. Manual city typeahead
3. "Use my location" optional button (18+)
4. OS location permission on first launch (avoid for teens)

**Do not** conflate "coarse location only" with "must ask GPS once." City selection **is** coarse location and is **lower friction** than GPS.

### Q3. Meetup RSVP without mating/meetup-grade verification

**Short answer: For 18+ adults, bulletin-board RSVP without extra KYC is adoption-supportive (PAW-74/75). For 13+, RSVP without VPC + supervision + hard safety architecture is not viable — and specialists recommend meetups be hard-blocked for minors entirely.**

#### 18+ path (aligned with PAW-74)

| Surface | Verification needed | Friction level |
|---------|---------------------|----------------|
| Browse city meetups | App-wide 18+ DOB + PAW-53 integrity | Low |
| Host / RSVP | Same + `assert_adult_features_ok` server-side | Low — **not** growth-killing |
| Mating / Paw / intro chat | Base attestation + **step-up** (Phase 1b) | Moderate — acceptable if copy is upfront |

Meetup.com / FB Events model works for **self-declared adults** because offline gathering is **contextual and group-based**, not 1:1 romantic pairing. PAW-74 Legal input: no Aadhaar required for adult meetups — PAW-53 server asserts are the integrity layer, not signup friction.

#### 13+ path (proposed pivot)

| Concern | Why RSVP is problematic |
|---------|-------------------------|
| **Legal PAW-70** | Meetups = **hard block** for teens; no parental override |
| **QA PAW-72** | Real-world coordination = very high §9(2) well-being exposure |
| **DPDP** | Processing child data for event RSVP (venue, time, pet photos, host adjacency) requires **VPC before any data** |
| **Adult↔minor adjacency** | Invite graph does not vet adults; bulletin board exposes minors to adult-hosted events |
| **Store review** | Apple/Google child-safety questionnaires for apps allowing minor RSVP to stranger meetups |

**Product Strategist framing:** "RSVP without mating-grade verification" is the **wrong comparison for 13+.** The bar is not mating KYC — it is **whether minors should RSVP to real-world stranger events at all.** Specialist answer: **no.**

**If Founder still wants teen locality value:** city-scoped **view-only** event discovery with **no RSVP** and no host capability is theoretically lighter — but still likely fails Legal/QA without full teen architecture, and offers weak activation (browse-only bulletin board). Not recommended.

### Q5. Pet-first identity preservation

**What the proposal preserves:**
- Moments attributed to pets (not owner selfies as primary)
- Meetup cards showing **pet host names** (existing Pawple convention)
- No mating = avoids dating-app identity drift for younger users

**What the proposal risks:**

| Risk | Mechanism |
|------|-----------|
| **Event-app identity** | Bulletin board + RSVP foregrounds **time/place/attendance** over "quiet collection of memories" |
| **Utility-heavy feel** | City-scoped event discovery is Meetup.com / FB Events — not Pawple's calm journal core |
| **Split product personality** | 13+ users get events; 18+ users get mating — fragmented brand story |
| **Empty states** | Low pet-density cities → empty bulletin board contradicts premium calm positioning |

**Pet-first preservation guidance (if any teen surface ever ships):**
- Lead with **pet journal** and private Moments — events secondary, never home-tab hero
- No attendance counts, popularity, or "trending in your city"
- Copy: pet names, not "find playdates near you"
- **No push** for event reminders (already deferred)

**For 18+ Phase 1a bulletin board:** pet-first is **preservable** if meetups remain a **quiet secondary surface** — feed/journal first, city events discoverable but not loud. The 13+ pivot **forces** events into the teen value prop because mating is removed — increasing event-app drift for the younger tier specifically.
